# Wandering 散步

[English](README.md) | **简体中文**

> 会走神的记忆：给长期陪伴型 AI Agent 的卡片、关系线与联想游走。

![记忆里的一次散步：起点是和刚才那句话最像的卡片，沿着关系线走到相邻卡片，光逐步变暗，跑题时停下。](docs/walk.svg)

Wandering（散步）是一个记忆系统，服务对象是和同一个人长期相处的 AI Agent。它把记忆存成一张张**卡片**，用带标签的**关系线**把相关卡片连起来；回忆时**游走**：从和当前消息最像的卡片出发，沿关系线一张一张走几步。

这是一个研究原型，用 Python 写成，数据存在 SQLite。除了两处可选的模型调用（打标、做梦），全部在本地运行。

## 为什么做

大多数 Agent 记忆的工作方式像搜索：把过去的对话切块、算向量，返回和新消息最接近的前 k 块。这样能找到*字面上像*的记忆，找不到*有关联、但说法不同*的记忆。

举个例子，用户说：

> 下周就截止了，我还一点没动。

相似度检索会返回其他提到"截止"的消息。一个认识用户很久的朋友还会想起：上次也是这样，提醒听起来像催，两个人为此吵了一架，之后约好以后换一句轻松的暗号来提醒。这几段记忆里都没有"截止"两个字，在前 k 检索里排得很靠后。

Wandering 顺着关系线走到它们：*截止 → 拖延 → 那次吵架 → 暗号*。

## 一次游走长什么样

下面是虚构演示数据（`demo/`）的真实输出。用户是虚构人物林舟，建筑系学生。

```
输入：「截止日期又要到了，我一点没动」

起点 #2 「老师说'你们的工作量永远会膨胀到填满截止日期'，说完看了我一眼。」 (相似 0.56)
  → 因为拖延→导师那句'工作量膨胀到截止日期'（same_concept）：#1 「评图还有六天，我模型连底板都没切。」  我当时：有点替她慌，又不敢先慌给她看。
  → 因为截止前的慌，换了个考试又来一次（same_feel）：#38 「九月二号开学快题考试，三小时画一个社区图书馆。」  我当时：三小时，我已经开始替她分时间了。
  ↩ 回到起点 #2，换一条线
  → 因为导师那句话→它的名字：帕金森定律（same_concept）：#3 「原来这叫帕金森定律？我还以为是种病。」
  → 因为知道拖延只是个定律而不是她的毛病，提醒就可以换成暗号（same_concept）：#26 「那你以后想提醒我，就说'小船该靠岸了'。」  我当时：暗号比道理好用。
停：走满4步
```

走完这一趟，Agent 知道该用约好的暗号提醒，用不着讲道理。用 `--seed 7` 可以复现（见快速开始）。

## 工作原理

### 卡片

一张卡片是一段记忆。

| 字段 | 内容 |
|-|-|
| `quote` | 用户的原话 |
| `what` | 发生了什么，以 Agent 的第一人称写（"我听到用户说……""我答应了……"） |
| `feeling` | Agent 当时自己的反应。只有 Agent 本人能写，打标模型留空 |
| `gate` | 这张卡能被多随意地想起（见下方"闸门"） |
| `at`、`source`、`why` | 什么时候发生；是谁的话（用户本人的，还是转述别人的）；为什么重要 |

卡片只增不改：SQLite 触发器拦住 `UPDATE` 和 `DELETE`。记错了就新加一张**更正卡**，写明正确的版本，连到旧卡上。新卡排序更靠前，所以想起来的会是更正后的那张。

### 关系线

关系线是两张卡之间的无向连接，带一个强度（0–1）和一句必填的 `because`，说明为什么相连。

| 类型 | 连接的是…… |
|-|-|
| `same_time` | 同一段时间里发生的 |
| `same_person` | 关于同一个人的 |
| `same_thing` | 关于同一个物件、地点或事件的 |
| `same_feel` | 感受相近的 |
| `same_concept` | 共享同一个概念的 |

### 游走

1. **起点**：和当前消息最像的卡片。
2. **每一步**走到一张相邻卡片，按 `强度 × 显著度 × 新近度` 做 softmax 抽选。写了 `feeling` 或 `why` 的卡显著度更高；新近度随时间衰减。
3. 每走一步，"光"乘以 0.75。光耗尽、走满 4 步、或者走到一张和当前消息无关的卡时**停下**（最后这张卡保留，标记为"走神想到的"）。
4. 每次游走有一次 15% 的机会回到起点，换一条线再走。

所有阈值都是手调的，写在 `wandering/config.py`。

### 闸门

有些记忆不应该被随便翻出来。每张卡有四种闸门之一：

| 闸门 | 用于 | 什么时候能被想起 |
|-|-|-|
| `normal` | 日常记忆 | 随时 |
| `tender` | 痛苦或敏感的记忆：生病、失去、吵架 | 只能作为游走的*起点*，且相似度要高（≥ 0.6）。游走途中不会拐进去 |
| `intimate` | 私密的亲昵时刻：小名、晚安习惯 | 只在当前消息本身是亲昵语气时（`config.py` 里的词表，如"晚安""想你"） |
| `explicit` | 性相关内容 | 只在外部分类器判定当前消息属于亲密语境时（`WANDERING_INTENT_GATE`） |

### 每张卡两个向量

每张卡算两次向量：`quote + what` 合在一起算一次，`quote` 单独算一次，匹配时取高分。短原话和一大段描述拼在一起后信号会被稀释（我们的测试里相似度 0.51 对 0.77）。

### 做梦（可选）

`wandering.dream` 在夜里运行。一个模型把几段随机的原始对话碎片拼成一个梦，再用第二个提示词扮演刚醒的 Agent 回忆它。只留下"记得"的两三句，包在 `<dream>` 标签里，方便下游代码把它和真实事件分开。完整的梦直接丢弃。

## 和切块检索的区别

| | 切块 RAG | Wandering |
|-|-|-|
| 记忆单位 | 一段文本 | 一张卡：原话、发生了什么、Agent 的感受 |
| 谁来写 | 文本切分器 | 打标模型，然后 Agent 自己补 |
| 记忆之间的联系 | 无 | 关系线，每条都写明原因 |
| 召回方式 | 按相似度取前 k | 从最像的卡出发，沿关系线游走 |
| 修正记忆 | 覆盖或重建索引 | 新加一张更正卡 |
| 敏感记忆 | 和普通文本一样处理 | 有闸门 |

## 适用场景

适合：

- 和同一个人长期相处的陪伴型或个人 Agent，记忆周围的上下文和感受很重要
- 研究联想式回忆和前 k 检索的差别

不适合：此记忆系统不是给编程 agent 用的即插即用记忆层，也不是文档知识库。

## 常见问题

**它能替代向量检索吗？**
不能。起点卡就是靠向量检索找的；游走补上检索会漏掉的部分。回答事实类问题时，单靠一次游走比前 k 检索差（见"实验结果"）。计划中的用法是给 Agent 前 k 张卡加一次游走。

**卡片从哪来？**
`wandering.tagger` 把原始对话发给一个聊天模型（*打标模型*），用 `tagger_prompt.md` 里的提示词，拿回 JSON 格式的卡片和关系线。输入每行以 `用户:`（用户）或 `我:`（Agent）开头；卡片里用中性的"ta"指用户。任何兼容 OpenAI 接口的聊天 API 都可以。我们用的是 DeepSeek，便宜、中文好，推荐；想换就改 `WANDERING_TAGGER_BASE_URL` 和 `WANDERING_TAGGER_MODEL`。也可以用 `add` 和 `link` 手写卡片。

**为什么 `feeling` 要 Agent 自己写？**
打标模型事后读记录，只能猜 Agent 当时的感受，猜出来的往往千篇一律。这个字段留给 Agent 本人，允许留空。

**为什么只增不改？**
防止记忆被悄悄改写。每一次修改都是一张可追溯的新卡。

唯一的例外是隐私：不该存的东西误存了，用 `python -m wandering purge <卡片id> --yes` 彻底删掉。它会连同关系线、索引一起删，再压缩数据库，原文不会留在文件里。

**需要 GPU 吗？**
不需要。自带的向量服务用 fastembed 在 CPU 上跑 `BAAI/bge-small-zh-v1.5`。任何兼容 OpenAI 的 `/v1/embeddings` 接口都能用。

**哪些数据会离开本机？**
默认情况下三处：
- **打标**：当前这段原始对话，加上已有卡片的原话、内容和时间（用来连线），会发给打标模型。卡里可能有别人的事。
- **做梦**：随机抽的原始聊天片段会发给做梦模型。只过滤了露骨内容，健康、情绪、家人这些都可能在里面。所以做梦默认不跑，要加 `--send-raw` 或设 `WANDERING_DREAM_SEND_RAW=1` 才会发。
- **向量**：默认走本机的 `127.0.0.1`，不出门。如果换成远程接口，卡片原文和查询都会发过去；此时必须用 https，明文 http 会被拒绝。

卡片、关系线、向量本身存在本地 SQLite 文件里，文件权限只有你自己能读。

**能用于英文吗？**
代码本身和语言无关，但打标提示词、演示数据、默认向量模型都是中文的。用英文需要换英文向量模型、翻译提示词。尚未测试。

## 快速开始

Python 3.10+。

```bash
pip install -r requirements.txt

# 1. 准备一个向量接口（任何兼容 OpenAI 的 /v1/embeddings 都行）
pip install fastembed
python tools/embed_bridge.py            # 在 127.0.0.1:8749 提供 BAAI/bge-small-zh-v1.5

# 2. 载入虚构演示数据，走一趟
python -m wandering load demo/cards.jsonl --db demo/demo.sqlite
python -m wandering walk "截止日期又要到了，我一点没动" --db demo/demo.sqlite --seed 7 --dry-run

# 测试
python -m unittest discover -s tests -t .
```

没有向量接口时，Wandering 退回关键词起点（FTS5 trigram），并跳过跑题检测。其他命令：`add`、`link`、`show`、`stats`、`reembed`、`purge`（`python -m wandering -h`）。

### 演示数据

`demo/` 里的一切都是虚构的：建筑系学生林舟、小狗土豆、家里一场生病的虚惊。`demo/queries.txt` 列了十条输入和各自演示的点：漂移防护、更正卡压过旧记忆、从 tender 卡起步、intimate 闸门、以及一条不该触发游走的无关闲聊。

### 环境变量

| 变量 | 默认值 | 用于 |
|-|-|-|
| `WANDERING_HOME` | `~/.wandering` | 默认数据库位置 |
| `WANDERING_EMBED_URL` | `http://127.0.0.1:8749/v1/embeddings` | 向量 |
| `WANDERING_TAGGER_API_KEY`（或 `DEEPSEEK_API_KEY`） | – | 打标 |
| `WANDERING_TAGGER_BASE_URL`、`WANDERING_TAGGER_MODEL` | DeepSeek | 打标（任何兼容 OpenAI 的聊天 API） |
| `OPENAI_BASE_URL`、`OPENAI_API_KEY` | – | 做梦（如 OpenRouter） |
| `WANDERING_DREAM_MODEL` | `x-ai/grok-4.7` | 做梦 |
| `WANDERING_DREAMER` | `Agent` | Agent 的名字，用在做梦提示词里 |
| `WANDERING_INTENT_GATE` | 未设置 | `explicit` 闸门用的可选外部分类器 |

## 实验结果

在 [LoCoMo](https://github.com/snap-research/locomo) 的一段对话上做的小规模本地测试（`aml/`；`locomo10.json` 需自行下载到 `aml/data/`，本仓库不分发）。40 道题。同一个 LLM 根据给它的记忆回答每道题，再给答案打分。

| 给答题模型的记忆 | 准确率 | 平均上下文 |
|-|-|-|
| 原始切块，前 5 | 45% | 2475 字 |
| Wandering 卡片，前 10 | 47.5% | 1933 字 |
| 一次游走 | 32.5% | 1015 字 |

卡片的分数和原始切块差不多，文本少 22%，时间类问题更好（卡片带日期）。单次游走分数较低：这个基准考的是事实，游走的用途是带出相关的记忆。

## 局限

- 一段对话、40 道题、同一个模型打分。只能算基本检查。
- 只在中文上构建和测试过。
- 游走没有学习参数，所有阈值都是手调的。
- 还没有稳定的 API，之后可能有破坏性改动。
